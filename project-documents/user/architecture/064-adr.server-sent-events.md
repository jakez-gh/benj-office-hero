# ADR-064: Server-Sent Events for live route updates

## Status

Accepted

## Context

The Routes page polls `GET /vehicles/{id}/locations/latest` every 30 s for GPS
position. Route *status* events (stop arrived, stop complete, route cancelled)
have no live delivery path — a dispatcher must reload the page to see a
technician's progress updates.

Two push mechanisms were considered: WebSocket and Server-Sent Events (SSE).

## Decision

Use **Server-Sent Events (SSE)** via a `GET /routes/{id}/events` endpoint.

Rationale:
- Route events are **unidirectional** (server → browser). SSE exactly models
  this; WebSocket's bidirectional framing adds complexity for no gain here.
- SSE works over HTTP/1.1 and HTTP/2 without an upgrade handshake, so Fly.io's
  proxy layer requires no additional configuration.
- The browser's native `EventSource` API handles reconnection automatically.
- FastAPI `StreamingResponse` with `text/event-stream` is idiomatic and requires
  no third-party library.

## In-memory pub/sub

A lightweight asyncio-based hub (`core/route_events.py`) is sufficient for
single-instance Fly.io deployments. Subscribers are `asyncio.Queue` objects keyed
by `route:<route_id>`. If the deployment scales horizontally, swap the hub for a
Redis pub/sub backend without changing the SSE endpoint contract.

## Authentication

The `EventSource` browser API does not support custom request headers. The JWT
token is passed as a `?token=<jwt>` query parameter. The SSE endpoint extracts
and validates it via `security.decode_token`. In test mode, the standard
`X-Test-*` middleware headers are injected by Playwright's `page.route()`
interceptor and continue to work transparently.

## GPS location polling

The 30 s poll for vehicle GPS position is **not** changed by this ADR. GPS fixes
arrive via the tech mobile app's periodic POST; the backend will publish SSE
events whenever a new GPS fix is stored, allowing the admin web to drop the poll
entirely in a future slice.

## Consequences

- Adds `core/route_events.py` (event hub) and `GET /routes/{id}/events` (SSE).
- Modifies route stop handlers to publish events after each state change.
- Requires `useRouteEvents` hook in admin-web that creates an `EventSource` and
  merges incoming state patches into `RoutesPage` local state.
- Not horizontally scalable without a Redis pub/sub backend (acceptable for
  current single-instance deploy).
